# OpenConvert

OpenConvert is a small web app for real image/audio/video conversion and live media-link analysis. It only offers file conversions present in the engine-version-bound registry generated by running the actual conversion matrix. The downloader uses yt-dlp to inspect each submitted URL; it does not claim that every platform or every video works.

## Run locally

Requirements: Python 3.11+, Node.js 20+, FFmpeg/ffprobe, and Pillow. To test platform URLs, install the pinned yt-dlp dependency and have outbound DNS/HTTPS access.

From the repository root (not `~` and not inside the Python prompt):

```sh
python3 -m pip install -r services/api/requirements.txt
python3 services/api/verify_registry.py
```

Start the API in the first terminal:

```sh
python3 services/api/standalone.py
```

Start the web app in a second terminal:

```sh
npm ci --prefix apps/web
npm run dev
```

Open <http://localhost:3000>. From the repository root, `npm run dev` also starts the web app and `npm run api` starts the API. If you are already in `apps/web`, use `npm run api` there. Do not enter shell commands at the Python `>>>` prompt; type `exit()` first.

Platform downloading is enabled by default when yt-dlp and ffprobe are installed; set `ENABLE_PLATFORM_DOWNLOADS=false` to turn it off. The page analyzes a URL after typing or pasting it and displays only the qualities returned by yt-dlp for that URL. This repository could not test a real external platform URL because its environment has no working public DNS/network access. Therefore platform integrations remain **unverified until tested on your host**. Unsupported, unavailable, login-only, protected, or restricted media will fail; the app does not bypass access controls.

## Deploy for external testing

`vercel.json` configures the Next.js frontend and Python/FFmpeg API container as two Vercel Services. Import this repository with the repository root as the project root, then set the Vercel project's **Framework Preset** to **Services** in Build & Development Settings. The API service uses the container runtime. The Vercel API profile limits uploads and download results to 4 MiB because Vercel Functions have a 4.5 MB request/response payload limit. Large media operations will exceed this profile; use the Docker Compose profile on a container host for larger files. Check `/api/health` and `/api/capabilities` after deployment. If your Vercel account does not enable Services/container deployment, deploy the frontend and API separately, with the API on a Docker-capable host and `NEXT_PUBLIC_API_URL` set to its HTTPS origin at web build time.

For Docker Compose on a Docker host:

1. Copy `.env.example` to `.env`.
2. Set `NEXT_PUBLIC_API_URL` to the HTTPS API address reachable by the browser. Set `CORS_ORIGINS` to the exact HTTPS web origin. These values must be set before building the web image.
3. Build and start with `docker compose build && docker compose up -d`.
4. Check `https://YOUR_API_HOST/api/health` and `/api/capabilities`.
5. Confirm outbound HTTPS/DNS works; platform downloads are enabled by default in the provided configuration. Set `ENABLE_PLATFORM_DOWNLOADS=false` to disable them.
6. Paste a public media page URL into the site. Analyze it, choose an option returned for that link, then download and open the result.

If the web/API use separate domains, configure TLS and ensure the browser can reach the API directly. Keep the API behind a reverse proxy with request-body/time limits at least as large as the configured upload limit. The API currently processes requests synchronously and keeps request/result bytes in memory. It is intended for controlled testing and small files, not an unrestricted public service. No accounts, durable job history, queue, malware scanner, or production rate-limit system is implemented. Do not expose it to untrusted high-volume traffic without adding those controls.

Useful commands:

```sh
docker compose logs -f api web
docker compose down
python3 -m unittest discover -s services/api/tests -v
npm run build
```
